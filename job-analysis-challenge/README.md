## Actual runtime workflow after deployment

The trainer should use the newly deployed Apps Script /exec URL, **not GitHub Pages preview**, for cross-device play. The Apps Script backend serves the current interface assets from this repository inside its own HTMLService context, so frontend and backend communicate via Google-supported google.script.run (no CORS bridge required).

1. Teacher logs in with private code generated by setupChallenge.
2. Teacher switches PRE / POST; the current round and approved results are stored in Google Sheets.
3. A group uses its own code and assigned case link; submission is stored to Submissions before Gemini is called.
4. Gemini proposes evidence-based criterion scores using the private Instructor AnswerKey and case-specific rubrics (5 criteria, sum 100).
5. Teacher sees full trainee answers, proposed scoring, suggested improvements and Pre/Post development, then approves and reveals scores.
6. Projector Arena polls the backend approximately every 8 seconds; approved scores set the color bands.

## Output guarantees and limitations

- No hidden answer keys or credentials committed to GitHub.
- Current GitHub Pages preview is local-only; the real Web App requires deployment.
- External Google Docs URLs are stored but not automatically read. Gemini evaluates text submitted inside the game and never claims to have reviewed linked files.
- Scores must be approved by the human trainer before public reveal.
- Frontend and backend parsing and business logic passed local simulations, but real Google authorization and cross-device end-to-end testing are still pending.
- Different cases have different rubrics; focus on within-group PRE→POST improvement, not raw group ranking.
