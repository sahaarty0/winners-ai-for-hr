# تشغيل Winners Job Architecture Challenge — تعليمات المحاضر

**حالة المشروع:** قاعدة البيانات وواجهات اللعبة وكود Backend جاهزون. Google Apps Script لم يُنشَر بعد؛ نشره يستلزم تفويضًا من مالك حساب Google. مفتاح Gemini غير مطلوب لتسجيل الحلول، لكنه مطلوب للتقييم الآلي.

## قاعدة البيانات

https://docs.google.com/spreadsheets/d/10kRmWXTpNcVMo0sx3IJb73WrZr4gLe_3RJk7CE0Qg1M/edit

## 1 — تشغيل Backend (مرة واحدة)

1. افتح قاعدة البيانات.
2. Extensions → Apps Script.
3. افتح ملف Code.gs، امسح المحتوى القديم، والصق **الكود الكامل** من:
   https://github.com/sahaarty0/winners-ai-for-hr/blob/main/job-analysis-challenge/backend/Code.gs
4. Save، ومن قائمة الدوال اختار setupChallenge ثم Run.
5. وافق على صلاحيات Google المطلوبة، ثم افتح تبويب Guide في الشيت.
6. Guide!B10 يحتوي كود المحاضر، وGuide!B11:B14 أكواد الجروبات الأربع.

احتفظ بالشيت خاصًا بالمحاضر ولا تشاركه مع المتدربين. إعادة تشغيل setupChallenge لا تغير الأكواد الموجودة. يوجد Trigger كل 15 دقيقة لإعادة محاولة تقييم أي تسليم معلّق، بمجرد إضافة مفتاح Gemini.

## 2 — نشر رابط اللعبة الحقيقي (مرة واحدة)

1. Apps Script → Deploy → New deployment.
2. النوع: Web app.
3. Execute as: Me.
4. Who has access: Anyone.
5. Deploy، وافق على أي صلاحيات إضافية، وانسخ رابط Web App الذي ينتهي بـ /exec.

**رابط /exec هو اللعبة الحية**: لوحة المحاضر والـ Arena وصفحات الجروبات تُعرَض من Apps Script باستخدام واجهة Winners المحفوظة على GitHub. لا تحتاج إلى رفع أي HTML إضافي.

## 3 — Gemini API (آخر خطوة، يمكن تأجيلها)

1. Apps Script → Project Settings → Script Properties.
2. Add script property:
   - Property: GEMINI_API_KEY
   - Value: مفتاح Gemini الخاص بك.
3. اختياري: GEMINI_MODEL = gemini-2.5-flash (قد تختلف النماذج المتاحة حسب حسابك).
4. لا تضع المفتاح على GitHub أو في صفحات اللعبة أو في Google Sheets.
5. الـ Rubric يحتوي خمسة معايير لكل حالة، مجموعها 100 نقطة. Gemini يقترح تقييمًا تفصيليًا، والمحاضر يعتمد الدرجة النهائية.

## طريقة التدريب

1. المحاضر يفتح رابط /exec ويدخل كوده من Guide!B10 ويضغط اتصال.
2. يختار PRE، ويفتح Game Arena على جهاز العرض.
3. يشارك رابط كل Group من لوحة المحاضر مع قائد المجموعة وكودها الخاص.
4. كل جروب يكتب إجابات الأسئلة وملخص العمل، ثم يضغط تسليم؛ الإجابة تُحفظ في Submissions أولاً.
5. المحاضر يراجع تحليل Gemini في لوحة المحاضر، ويعتمد الدرجة، ثم يفعل إظهار النتائج المعتمدة.
6. يختار POST ويرسل روابط الجولة الجديدة، ثم يعتمد النتائج ويراجع الفرق بين PRE وPOST.

## اختبار القبول النهائي

- فتح الرابط من هاتف منفصل.
- إدخال كود جروب غير صحيح: يتم الرفض.
- تسجيل تسليم صحيح: يظهر صف في Submissions.
- تكرار نفس التسليم: يتم الرفض.
- درجة Gemini لا تظهر قبل موافقة المحاضر.
- بعد الاعتماد والإظهار، يتغير لون الكارت تلقائيًا.
- تغيير الجولة يُخفي النتائج لحين الاعتماد.
- في حالة غياب المفتاح أو تجاوز الحصة، لا نفقد الحل ويمكن تقييمه يدويًا.

## حدود مهمة

- الكود خضع لاختبار منطقي ومحاكاة قبل النشر، لكن **لم يعمل بعد داخل حساب Google الخاص بك**؛ اختبار Web App الحقيقي مطلوب.
- رابط Google Docs الخارجي يُحفَظ فقط: **Gemini لا يقرأ محتوى الرابط** تلقائيًا، وإنما يقيّم الإجابات والملخص المدخلين في اللعبة.
- قاعدة البيانات سرية، واستخدام Web App بنظام Anyone يتطلب حماية كود المحاضر وكود كل جروب.
- نقيس التطور داخل نفس الجروب ونفس الحالة، وليس بترتيب خام بين حالات مختلفة.
